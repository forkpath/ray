Architecture verdict

可扩展，且已具备治理闭环

App 作为 composition root；contract、data-access、UI 和 platform adapter 通过 type/runtime/domain 三维标签约束。Auth、Billing、UI、Server platform 已拆出明确边界；Web/Native 不再直接依赖 Prisma、NestJS 或 Node-only Auth/Billing 实现。

数据库当前实现身份、组织、计费、Webhook 幂等、在线迁移台账、可恢复回填与 Worker Inbox。 Better Auth 1.6.26 的 10 个模型通过固定 CLI 的逻辑/物理双契约校验；本地扩展只有显式白名单。

04 / PostgreSQL contract

18 张表，四类职责

public schema 承载 Auth、组织与平台控制记录；billing schema 隔离计费状态。所有表均由受版本控制的 Prisma 物理契约描述。

What the database does

身份与租户不是附属能力，而是数据主轴

  • 用户、会话、OAuth/密码、验证、Passkey、2FA
  • 组织、成员、邀请、自定义角色与权限
  • 用户/组织双计费归属、订阅、订单与 Webhook 状态机
  • 在线迁移、可恢复回填、冲突隔离与消息 Inbox

暂未实现完整会计账本：Order 没有 amount、currency、tax、refund 或 invoice 明细；这是已明确排除的独立 Ledger 项目。

受治理模型全部吻合

对当前 stable：吻合

运行时、Expo、Passkey 与固定 CLI 全部锁定 1.6.26；截至审计日 npm `latest` 也是 1.6.26。CI 从临时目录生成候选 schema，并比较字段、类型、可空性、默认值、索引、表名、列名与 schema。

User/Organization 的 billing relation，以及 Member、Invitation、OrganizationRole 的业务索引/唯一约束通过最小白名单管理；陈旧白名单本身会令检查失败。

对 1.7 RC：刻意不吻合

1.7.0-rc.4 仍是候选版本，Account 身份模型引入 issuer/providerAccountId 迁移与冲突处理。本轮遵循稳定补丁策略，不提前采用 RC。

升级 1.7 必须独立执行：冻结认证写入、审计 provider/account 冲突、Expand 新列、回填、双读验证，再切换和 Contract。

Affected CI

Action 没有被弃用：仓库固定使用 v5.0.1 的完整 commit SHA；npm/GitHub 最新仍为 v5.0.1。它负责寻找 dev 最近成功 CI；resolver 再校验 SHA ancestry 与 Nx Cloud，并在失败时安全降级全量。

PR/dev 使用 affected；main、Tag、schedule、manual 与 CI/部署控制面变更强制 full。Fork PR 不获得 Nx Cloud secret。确定性任务最新 dev 复验为 124/124 remote hit。

07 / remaining engineering work

不要把“代码完成”误读为“生产完成”

以下不是迁移失败，而是必须明确保留的风险与后续工作；优先级基于进入生产前的影响面。

P0

首次部署与真实恢复演练

未证明

当前没有生产部署。上线前必须在隔离环境执行备份恢复、Expand、旧/新应用兼容、digest 回退、蓝绿切流、WebSocket drain 与队列积压阈值验证。

P0

Billing Contract 门禁

不得提前

`referenceId`、可空 owner 与 legacy 写入仍是正确的回退保险。只有 shadow mismatch 连续为零且 14 天/两次发布门禁满足后，才能验证 FK、加 XOR CHECK、删除 legacy。

P1

敏感认证材料保护

Account 存储 access/refresh/id token，TwoFactor 存储 secret/backup codes。schema 无法证明应用层加密；上线前应核验字段级加密、密钥轮换、最小 DB 权限、日志脱敏与备份访问控制。

P1

Nx 24 前置清理

34 个配置文件仍引用已提示将在 Nx 24 移除的 `nxViteTsPaths` / `nxCopyAssetsPlugin`。先迁移至 `vite-tsconfig-paths` 与 Vite `publicDir`/static-copy，再升级 Nx；当前 23.0.1 → 23.1.1 可由 Renovate 小步处理。

P1

物理默认值收紧

`WebhookEvent.processedAt` 已可空且应用 claim 时显式写 null，但旧数据库 default `CURRENT_TIMESTAMP` 仍保留。应在后续安全迁移中 DROP DEFAULT，避免非标准写入产生“未处理但有处理时间”的歧义。

P2

移除四个兼容 facade

`auth`、`billing`、`api-client`、`ui-shared` 仍标记 `boundary:facade`。在所有内部消费者稳定一个发布周期后，按依赖图逐个删除，避免新代码继续依赖混合入口。

P2

持续指标与 Sandbox nightly

最新 full PR 样本已较基线下降 56.4%，但仍需两周滚动 P50/P95；Stripe/RevenueCat sandbox 仅应在有隔离 tenant、密钥与清理策略的受控 nightly 启用。

P3

质量与体积债务

Studio lint 仍有 13 个 warning；Web 构建主 chunk 约 1.61 MB（gzip 482 KB）并触发 Vite 500 KB 警告。可在功能稳定后拆 route/provider chunk，并把关键 lint warning 逐步升级为 error。
